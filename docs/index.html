JSON API Builder

A traversal-driven Node.js project generator. V7 builds a client project from a JSON directory tree, inserts an ESTree-based Hono template, and connects nested route modules.

This document describes the implementation available in V7. It distinguishes working functionality from planned capabilities so the current scope is clear.

Current architecture: src/v7 contains reusable package code. test/v7 is a version-specific client project containing input, individual runners, a combined runner, tests, and generated output.

2. Input: the tree definition

test/v7/input/source-of-truth/tree.json currently defines the folder and file hierarchy:

{
  "api": {
    "routes.js": "routes.estree.json",
    "v1": {
      "routes.js": "routes.estree.json",
      "clinics": {
        "routes.js": "routes.estree.json"
      }
    }
  }
}
  • Object-valued nodes represent directories.
  • String-valued entries represent files.
  • The string value points to an AST definition relative to source-of-truth.
  • Traversal stages derive output locations from this tree.

The intended rule is that changing a child directory name in the tree changes its generated folder and route connection. V7 derives route import paths and mount paths from child names.

3. The processing stages

01 · Create foldersTraverses the tree and creates directory nodes under the client output folder.
02 · Create filesCreates empty files for string-valued leaves. Existing files are left untouched.
03 · Insert contentLoads the referenced ESTree JSON, generates JavaScript with Astring, and writes it to the corresponding file.
04 · Hook routesDerives child imports and Hono app.route() registrations from the tree.

4. Route composition

Given the tree above, the intended generated hierarchy is:

output/
└── api/
    ├── routes.js
    └── v1/
        ├── routes.js
        └── clinics/
            └── routes.js

The root route module imports and mounts the V1 module:

import { Hono } from "hono";
import v1Routes from "./v1/routes.js";

const app = new Hono();
app.route("/v1", v1Routes);

export default app;

The V1 module similarly imports and mounts Clinics at /clinics. The route variable name, relative import path, and mount path are derived from the child directory name.

5. Individual tasks and combined execution

Each test runner exports a run() function. It runs automatically when executed directly, but can also be imported by the combined runner.

import { run as createFolders } from "./create-folders.js";
import { run as createFiles } from "./create-files.js";
import { run as insertContent } from "./insert-content.js";
import { run as hookRoutes } from "./hook-routes.js";

export function run() {
    const foldersResult = createFolders();
    createFiles();
    insertContent();
    hookRoutes();
    return foldersResult;
}

This means the combined test runner reuses the same individual test operations instead of implementing a second copy of their sequence.

6. Run V7

Install

npm install

Run individual tasks

npm run v7:folders
npm run v7:files
npm run v7:content
npm run v7:hooks

Run the combined pipeline

npm run v7:build

Run automated tests

npm run v7:test

Generated output is written to test/v7/output/. The V7 test runners pass test/v7 as the client root; generated files are not written into src.

7. Public package API

The package root entry point currently re-exports V7 functionality. The implementation accepts a clientRoot option and defaults to the current working directory.

import {
    createFolders,
    createFiles,
    insertContent,
    hookRoutes,
    build
} from "json-api-builder";

build({
    clientRoot: "./my-client-project"
});

The expected client input layout is my-client-project/input/source-of-truth/tree.json, with referenced AST definitions alongside it. Generated output defaults to my-client-project/output.

9. Design principles

  1. Keep project structure in a machine-readable tree.
  2. Use the same traversal mechanism for each independent stage.
  3. Keep filesystem and AST operations in stage-specific functions.
  4. Let the client run stages individually or compose them in order.
  5. Generate JavaScript from structured representations rather than relying on fragile text insertion.

10. Dependencies

  • json-traversal-core — traversal of the JSON tree.
  • astring — generation of JavaScript source from ESTree AST data.
